### 1 Step 진행 기능 관련 구상안
기본적인 자동 진행 기능을 기본으로 하되, 
더 효율적인 시각적 피드백을 위해 다음과 같은 기능을 구상합니다.  (구현되지 않을 수 있습니다.)
1. comparsion과 array_access 구분을 위하여 각 Area 테두리 색 변경
2. 내부 자체 진행후 전체 step수 산출하여 진행도 표시.
3. 각 알고리즘 별 상세 처리 로직을 표현 (N과 M을 비교하여 다음과 같은 연산을 수행...)  

그리고 구현중 다음과 같은 사항에 미리 생각해야할 수 있습니다.  
1. 일단 threadvalue.wait(timeout = N)으로 한다면
1step이 아닌 경우에는 delay값을 전달하면 되지만, 1 step으로 진행할 경우에는
timeout값에 전달되는 N값을 -1 등으로 하여 timeout이라는 요소를 넣지 않도록 하는게 옳아보입니다.
2. 한칸, 한칸... 진행하기에는 64개의 막대가 너무 많아보입니다. 그러니까 1step으로 하더라도
언제든지 정렬을 자동으로 수행할 수 있도록 하며, Delay를 사용자 임의로 수정할 수 있도록 하는것이
 바람직해 보입니다. (실제로 64개의 막대를 퀵정렬의 n log n으로 연산하여도 대략 150~170정도 나올겁니다.
 n²일경우 4096입니다. 이걸 직접 누르는건 사용자에 대한 고문입니다...)
3. 구상안 3번의 처리 로직을 자연어로 표현한다면 delay시간이 일정 이상일 경우에
 표기하는게 좀 더 좋아보입니다. 만약 step만 하면 사용자가 피곤하고요.. 그렇다고 무조건 표기하면..
 네. 10ms 단위로 텍스트 와라랄라 지나가서 이건 읽을수가 없습니다. 1초에 문장 100개는 너무하잖아요.
